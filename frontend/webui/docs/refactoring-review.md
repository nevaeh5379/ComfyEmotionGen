# WebUI 중복·복잡도 검토

검토 대상은 `frontend/webui/src`의 TypeScript/TSX 소스다. 생성물인
`dist`, 외부 의존성인 `node_modules`, 복사된 ComfyUI 런타임 스크립트인
`public/scripts`는 제외했다.

## 확인 방법

- ESLint의 기존 규칙으로 전체 소스를 검사했다.
- 일회성으로 `complexity` 15, `max-lines-per-function` 150을 적용해
  유지보수 위험이 큰 함수를 찾았다.
- 브라우저 다운로드, 저장 항목 갱신, `localStorage`, `fetch` 사용 패턴을
  검색해 동일 책임이 여러 곳에 구현됐는지 확인했다.
- 변경마다 `typecheck`, 대상 파일 ESLint, Prettier를 실행했다.

복잡도와 함수 길이 임계치는 품질 게이트가 아니라 리팩터링 순서를 정하기
위한 지표다. 현재 임계치를 넘는 복잡도 경고와 함수 길이 경고는 각각
74개다.

## 이번에 정리한 항목

### Blob 다운로드

`URL.createObjectURL`, 임시 링크 클릭, URL 해제를 직접 반복하던 6개 경로를
기존 `triggerBlobDownload`로 통일했다. URL 해제와 DOM 정리 정책이 한 곳에
모여 브라우저 자원 정리 누락 가능성이 줄었다.

### 이름 기반 저장 항목 갱신

템플릿, 워크플로우, 에디터 워크플로우 훅에 같은 형태의 “기존 항목 갱신
또는 새 항목 추가” 분기가 있었다. ID 생성과 배열 갱신을
`upsertNamedItem`으로 옮기고 각 훅에는 도메인별 필드 조립만 남겼다.

### CEG 템플릿 파서

`TemplateGeneratorPanel.tsx` 안의 복잡도 37짜리 파서를 독립 모듈로 옮겼다.
변수, 축 항목, 결합, 제외, 오버라이드, 본문 파싱을 작은 함수로 분리했다.
대표 문법과 빈 입력을 검증하는 `test:parser` 스크립트도 추가했다. 분리된
파서 모듈에는 복잡도 15 또는 150줄을 넘는 함수가 없다.

### Header 책임 분리

모바일·데스크톱에 중복된 큐레이션 그룹 선택과 작업 세션 제어를 공용
컴포넌트로 통합했다. 내비게이션, 생성기 제어와 저장 다이얼로그, 갤러리
필터, 테마 선택, 반응형 폭 계산도 각각 독립 컴포넌트 또는 훅으로 옮겼다.
드래그 임계값, 드래그 후 클릭 억제, 폭 캐시 유지처럼 코드만으로 의도가
분명하지 않은 제약에는 근거를 설명하는 주석을 추가했다.

`Header` 함수는 복잡도 115에서 77로, 길이는 1,733줄에서 915줄로 감소했다.
이번에 추출한 컴포넌트와 훅에는 복잡도 15 또는 150줄을 넘는 함수가 없다.
남은 복잡도의 대부분은 데스크톱·모바일 갤러리 명령 메뉴에 집중돼 있다.

대형 컴포넌트는 JSX만 별도 파일로 옮기기보다 상태 소유권과 명령 경계를
먼저 정해야 한다. 우선 사용자 동작을 검증하는 테스트를 추가하고, 순수
선택자와 변환 함수, 명령 훅, 표시 컴포넌트 순으로 분리하는 것이 안전하다.

## 추가 DRY 후보

- `localStorage`의 JSON 파싱과 오류 복구가 여러 훅과 컴포넌트에 흩어져
  있다. 데이터별 마이그레이션 규칙이 있으므로 무조건적인 범용 래퍼 대신
  스키마 검증을 받는 저장소 어댑터가 적합하다.
- 직접 `fetch`한 뒤 상태 검사와 오류 본문 해석을 반복하는 경로가 있다.
  `api.ts`의 공용 요청 계층으로 모으되 취소 신호, Blob 응답, best-effort
  요청을 서로 다른 정책으로 유지해야 한다.
- 파일 가져오기 UI가 설정 화면의 템플릿/워크플로우 섹션에서 유사하다.
  파일 선택과 JSON 읽기는 공통 훅으로, 병합 및 충돌 정책은 도메인 함수로
  분리할 수 있다.
